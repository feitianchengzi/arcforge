# 隔离执行验证

前测或复测目标 skill 时使用本文件。目标是模拟真实用户如何调用目标 skill，而不是让另一个 agent 带着“正在验证 skill”的背景完成任务。

隔离执行者先扮演普通 agent 接收真实用户请求。主 agent 只在执行结束后，通过第二段总结 prompt 收集执行痕迹、选择、命令、路径、错误、用户交互点和卡点。观察是否有问题、判断问题类型、决定是否优化 skill、设计修复方案，都是主 agent 的职责。

## 验证路径

人工桥接隔离验证是唯一验证路径。

主 agent 生成并交付人工桥接执行包，用户新开一个 agent 对话，先粘贴真实任务 prompt，让隔离 agent 像真实使用场景一样执行任务；任务结束后再粘贴事后总结 prompt，并把总结、必要 transcript 或阻塞点贴回主会话。交付执行包只表示进入 `awaiting_validation_transcript`，不表示验证完成。

主 agent 不把诊断、预期答案、问题分类、修复思路、测试目的或“请评价 skill 是否需要优化”的任务传给隔离执行者。

## 验证门禁

- 不调用任何平台工具来替代人工桥接。
- 不检查这类工具是否可用，也不把它们是否可用作为验证路径选择依据。
- 主 agent 必须生成可复制的人工桥接执行包，并让用户在新的 agent 对话里执行。
- 人工桥接执行包必须明确当前状态为 `awaiting_validation_transcript`，并要求用户回传事后总结、必要 transcript 或阻塞点。这个状态不能被写成“验证通过”“闭环完成”或“等待可选后续”。
- 不要因为当前会话不能直接调用自动代理工具就跳过隔离执行验证门禁；这和人工桥接方案无关。
- 不设计人工桥接失败、无法桥接、用户不愿桥接、平台不允许桥接、transcript 回放或受限 dry run 分支。

## 人工桥接执行包

主 agent 给用户以下内容，并把它作为本轮最后的可见动作，直到用户回传执行记录：

- 当前状态：`awaiting_validation_transcript`。
- 目标 skill 路径。
- 工作区和允许写入边界。
- 临时路径建议。
- 第一段可复制内容：真实任务 prompt。
- 第二段可复制内容：事后总结 prompt。
- 用户操作步骤：新开 agent 对话，先粘贴真实任务 prompt；按隔离 agent 的澄清或确认要求真实回应；任务结束、阻塞或请求确认后，再粘贴事后总结 prompt；把总结、必要 transcript 或阻塞点贴回主会话。

用户在新对话中充当真实用户。如果隔离 agent 提问，用户按真实情况回答；如果涉及破坏性、远程、凭证或真实写入操作，用户按平台和项目规则决定是否确认。主 agent 不替用户预设答案。

交付人工桥接执行包后，主 agent 必须停止在 `awaiting_validation_transcript` 状态。收到事后总结、必要 transcript 或阻塞点之前，不进入观察归因、修复、复测结论或 ArcForge 治理交接。

## 真实任务 Prompt 模板

第一段 prompt 只写真实用户会对 agent 说的话。它用于测试目标 skill 能否自然触发、自然读取自身规则并完成任务。

允许包含：

- 用户真实任务本身。
- 用户在真实场景中也会提供的仓库、路径、输入材料、约束或期望输出。
- 必要的写入边界或临时目录，例如“只写 `/private/tmp/...`”。
- 如果真实用户会显式点名 skill，可以写“执行 `<skill-name>`，做 `<task>`”；如果预期自动触发，就只写任务本身。

禁止包含：

- “你是验证执行者”“这是测试”“这是复测”“请验证 skill”。
- 目标 skill 的绝对路径，除非真实用户本来就会这样指定。
- 主 agent 的诊断、预期答案、问题分类、修复思路或观察重点。
- “不要评价 skill”“不要提出修复建议”“记录你读了哪些文件”这类测试控制语。
- 事后总结格式、执行痕迹清单或回传要求。

模板：

```text
<像真实用户一样提出任务。>
```

示例：

```text
执行 arcforge-skill-creator，创建一个用于整理客户反馈成产品待办的 skill。工作区是 /private/tmp/skill-test，只能写这个目录。
```

自动触发场景示例：

```text
帮我把“收到客户反馈后先分类、再判断是否进 backlog、最后生成待办摘要”的流程沉淀成一个可复用 skill。工作区是 /private/tmp/skill-test，只能写这个目录。
```

## 事后总结 Prompt 模板

第二段 prompt 只在隔离 agent 完成、阻塞或停在确认请求后发送。它用于把执行痕迹带回主 agent，不用于引导第一段任务执行。

```text
请总结你刚才这轮执行，方便我把结果回传给主会话。

请只基于你刚才实际做过的事情回答：
1. 你理解到的用户任务是什么。
2. 你实际触发或使用了哪些 skill；如果没有触发，说明你怎么处理。
3. 你读取了哪些关键文件或 reference。
4. 你执行了哪些命令、工具调用或文件操作。
5. 你读取、创建或写入过哪些路径。
6. 你向用户提过哪些问题，用户如何回答。
7. 第一个不清楚、失败、需要确认或需要权限的点是什么。
8. 原始错误、警告或不确定信息是什么。
9. 如果你停在计划、预览、drift 或确认请求处，下一步原本会写哪里。
10. 最终结果或阻塞点是什么。

不要评价 skill 好坏，也不要提出 skill 修改建议。
```

## 复测 Prompt 规则

复测仍然使用两段式，不要在第一段真实任务 prompt 中写“这是复测”。

- 第一段：换新的临时路径，重复同一个真实任务。
- 第二段：使用同一个事后总结 prompt。
- 主 agent 在收到总结后自行比较上一轮阻塞是否复现、是否出现新问题、是否需要继续修复。
