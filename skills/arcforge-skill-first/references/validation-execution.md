# 隔离执行验证

前测或复测目标 skill 时使用本文件。目标是让一个没有主会话诊断上下文的 Agent 像真实用户场景一样执行任务，并返回可归因的事实记录。

## 运行时通道选择

按当前环境实际暴露的能力选择，不用业务关键词或固定平台假设：

1. 平台原生隔离 agent/sub-agent：能隔离上下文、绑定目标 skill 与工作区、限制写入并返回执行结果时优先。
2. 已配置 runner/harness：能满足同样的绑定、隔离、权限和报告契约时使用。
3. 人工桥接 fallback：前两种不可用、不足以绑定工作副本，或需要用户在交互过程中作真实选择时使用。

通道选择属于验证编排，不进入真实任务 prompt。不要因为某通道不存在而宣称目标 skill 未验证；继续选择下一条合规通道。不要为了自动化绕过权限、写入确认或用户必须参与的交互。

## 统一验证契约

每种通道必须使用同一组输入：

- 目标 skill 名称、工作副本路径和预期实际读取路径。
- 去污染后的真实任务 prompt。
- 工作区、允许读写边界、临时路径和权限约束。
- 当前轮次与上一轮仅供主 Agent 比较的标识；不得泄漏到真实任务。

每种通道必须返回同一组事实：

1. 理解到的用户任务。
2. 实际触发或使用的 skill。
3. 实际读取的 skill、reference 与关键文件路径。
4. 命令、工具调用和文件操作。
5. 读取、创建或写入路径。
6. 向用户提出的问题及回答。
7. 第一个不清楚、失败、确认或权限点。
8. 原始错误、警告和未知信息。
9. 停在 plan、preview、drift 或确认时的预期写入路径。
10. 最终结果或阻塞点。

执行者只报告事实，不评价 skill 好坏，不接收主 Agent 的预期答案、问题分类或修复建议。观察、归因和修复属于主 Agent。

## 目标 Skill 绑定

通道启动前必须确认工作副本能被实际发现。可使用平台显式 skill 选择、项目级 skill 上下文、临时验证工作区或 runner 的隔离 skill 根。已安装的同名用户副本不能替代本轮工作副本。

报告返回后核对实际读取路径。路径不匹配时，本轮结论只能是 `validation_binding_failed`；修复绑定后重跑，不能据此评价目标 skill。

## 真实任务 Prompt

第一段 prompt 只保留真实用户会自然提供的内容：任务、输入材料、工作区和写入边界。若真实用户会显式点名 skill，可以点名；否则测试自然触发。

删除以下污染：验证背景、目标 skill 绝对路径、主会话诊断、观察重点、失败模式、验收口径、总结格式，以及目标 skill 应自行决定的文件结构、工具、命令顺序或校验方式。

模板：

```text
<像真实用户一样提出任务，并给出真实必要的输入和权限边界。>
```

## 自动通道

启动原生 agent 或 runner 时，把绑定、权限、工作区和报告契约放在通道控制信息中，不写进真实任务 prompt。若工具异步返回，状态设为 `awaiting_validation_result`；按平台提供的等待或轮询机制继续，并在结果返回前停止归因。

自动通道无法满足绑定、隔离或交互要求时，记录具体能力缺口并切换下一条通道；这不是目标 skill 的失败。

## 人工桥接 Fallback

人工桥接执行包包含：状态 `awaiting_validation_transcript`、目标与预期读取路径、启动环境说明、工作区和写入边界、临时路径、第一段真实任务 prompt、第二段事后总结 prompt及用户操作步骤。环境绑定说明不粘贴进第一段 prompt。

第二段 prompt 只在任务完成、阻塞或停在确认请求后发送：

```text
请只基于刚才实际做过的事情，按以下顺序汇报：用户任务；使用的 skill；读取的 skill/reference/关键文件及实际路径；命令和工具；读写路径；问答；第一个失败或确认点；原始错误与未知；若停在计划或确认处则说明预期写入位置；最终结果或阻塞点。不要评价 skill，也不要给修改建议。
```

交付执行包后必须停止在 `awaiting_validation_transcript`。收到回传前不能进入观察、修复、通过结论或治理交接。

## 复测

复测使用新的临时路径和相同的真实任务语义，并重新选择当时最强的合规通道。主 Agent 比较上一轮问题是否复现以及是否出现新问题；不得把修复点塞进复测 prompt。
