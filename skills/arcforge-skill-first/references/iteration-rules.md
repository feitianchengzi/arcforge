# 迭代规则

收到任一验证通道的事实报告后使用。隔离执行者提供事实，主 Agent 负责观察、分类、归因和修复。

## 问题分类

- 能力建模：预设 skill 是软件或纯文档，没有先理解知识、方法、内容、工具集成、软件支撑或混合性质。
- 目标路由：目标 skill 不足以覆盖领域、工作流、输入输出或不确定性处理；辅助能力反而接管任务。
- 契约结构：主流程、门禁、退出条件、reference 路由、metadata 或渐进披露不足。
- 用户要求固化：稳定要求未转成门禁、确认点、输出或明确边界，或把一次性纠错/业务上下文原样写入通用规则。
- 实现承载：没有发现已有工具/服务/模板，重复建设，或明明需要执行承载却只加 Markdown。
- 来源归属：把安装副本当成维护源，或工作副本未位于授权位置。
- 验证污染：真实任务 prompt 泄漏诊断、观察点、预期答案、验收口径、总结格式或内部实现形态。
- 验证绑定：实际读取的 skill 不是本轮工作副本。
- 通道协议：所选通道不能隔离上下文、限制写入、绑定工作副本或返回统一事实报告。
- 状态判断：等待结果时误报验证通过，或通道能力缺口被错误归因给目标 skill。
- 安全与权限：破坏性、远程、凭证或状态性动作缺少明确授权和确认。
- 治理交接：绕过 `arcforge` 确认规则执行 apply/share/push/覆盖，或遗漏合理的后续治理阶段。
- 环境/产品决策：失败来自沙箱、依赖、认证、外部系统或仍需用户决定的策略。

## 修复归属

- 能力性质、目标路由、契约、metadata、实现承载和来源工作副本问题交回 `arcforge-skill-creator`。
- prompt 污染、通道选择、绑定、统一报告和等待状态问题在 `arcforge-skill-first` 修复。
- 工具能力缺口若会普遍阻塞流程，记录输入、输出、权限、确认边界和所需承载；不要用隐性 workaround 掩盖。
- 具体项目名、客户名、临时偏好与一次性决策保留在项目上下文，不进入通用 skill。
- 代码只实现 schema、路径、digest、plan、确认、事务等确定性机制；语义分类与完成度判断留给 Agent。

修复保持最小范围，不重写无关内容。

## 复测

修改以下任一内容后需要复测：触发与路由、主流程门禁、确认点、写入边界、reference、metadata、工具调用、状态、验证通道、绑定、真实任务 prompt 或治理交接。

复测使用新临时路径和相同任务语义，重新按运行时能力选择最强合规通道。若只剩用户接受的产品缺口、用户要求停止或外部权限未批准，可以停止并明确状态。

## 通过标准

- 目标 skill 自然触发并读取了预期工作副本。
- Agent 根据真实场景理解能力性质，没有依赖固定业务枚举或关键词规则。
- 主流程、门禁、输出、不确定性与写入边界足以完成或正确停止任务。
- 真实任务 prompt 未污染，执行报告包含统一事实字段。
- 用户稳定要求被泛化固化，一次性上下文没有泄漏。
- 需要的承载被发现、复用或明确记录为缺口。
- 等待、绑定失败、环境失败和目标 skill 失败被正确区分。
- 验证结论有执行证据；ArcForge 治理建议保留用户确认。
