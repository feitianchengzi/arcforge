# Destinations - 交互规范

## 交互策略

### 核心任务

用户在 Destinations 页面管理配置组应用目标和已保存的应用关系，检查来源与目标之间的漂移，并在写入前复核每个 skill 的实际可用性模式和目标位置。

### 主路径

页面展示目标组合、目标历史和应用关系。用户选择目标组合后先检查漂移；标准 Agent 目标进入 availability-aware 计划，系统解析用户级常驻、项目级常驻和用户级按需目标，再展示来源推荐、最终模式、策略来源、实际目录、项目适用性提示、按需入口和旧路径清理候选。项目级常驻 skill 使用与本次项目根绑定的 Agent assessment；没有 assessment 时，用户只能在看过未决条件后作显式 override。用户确认后系统重新计算并执行计划，随后刷新漂移和应用关系。自定义目录保持 direct 应用路径。

### 决策点

- 用户选择标准 Agent 目标、Agent 项目目录或自定义 direct 目录。
- 标准 Agent 目标与自定义 direct 目录不能处于同一目标组合；用户分别保存两个组合。
- 用户在检查漂移后决定是否打开 availability-aware 应用计划。
- 项目级常驻 skill 没有可复用 assessment 时，用户决定返回 Agent 补充分析，或显式覆盖未决判断；系统不把用户覆盖显示为 Agent 结论。
- 用户决定是否保存应用关系；保存关系时必须确认全部旧 managed 目标，不保存关系时只清理明确勾选的候选。
- 用户根据阻断诊断返回目标组合、Profiles 或来源清单修正输入。

### 信息揭示

目标组合详情先展示来源、配置组、解析后的目标和最近漂移结果。应用计划按 skill 展示来源推荐、最终模式、策略来源和实际目录；项目级常驻项同时展示来源维护的条件、取证提示、澄清问题和已有 assessment。用户级按需项另行展示固定入口 skill 的用户级 Agent 目录。诊断、显式 override、cleanup 候选和关系保存约束只在计划确认阶段揭示。

### 状态流

无目标组合时显示空状态。新增或编辑目标进入 Sheet。目标组合保存后进入漂移检查；availability-aware 目标只有获得漂移报告后才可审查应用计划。缺少项目 assessment 时保持阻断，用户显式 override 后仅解除对应诊断；其它 error 仍阻断写入。执行期间禁用关闭和重复提交。成功后关闭计划、刷新漂移和关系；失败时保留计划、assessment、override 和其它选择以便重试或取消。

### 反馈与恢复

目标组合无 Agent、项目目录缺少 Agent、标准与 direct 目标混用时就地说明原因。计划 warning 保持可继续，error 阻断写入。项目 assessment 缺失时展示来源条件和 override 的事实含义；选择 override 后隐藏已解除的缺失诊断，不改变其它诊断。保存关系但 cleanup 未全部选择时说明解除阻断的两种方式：选择全部候选，或关闭关系保存。写入失败保留计划、assessment、override、cleanup 和关系保存选择。漂移检查失败保留上次成功结果和失败原因。

### 输入输出边界

输入包括目标组合名称、配置组、Agent 目标、Agent 项目目录、自定义 direct 目录、Agent assessment、用户显式 override、漂移检查、cleanup 选择、关系保存选择和最终确认。输出为只读可用性计划、项目适用性证据、漂移报告、实际写入结果、清理结果、目标历史和可选应用关系。目标组合或关系记录删除不删除已安装文件。

## 页面状态

| 状态 | 触发条件 | data-kit 关键控件 |
|------|---------|-----------------|
| 目标组合与漂移 | 进入页面或选择目标组合 | DestinationList、DriftSummary |
| 添加或编辑目标 | 用户点击新增或编辑 | Sheet |
| 可用性计划 | 标准 Agent 目标已有漂移报告，用户点击审查计划 | ConfirmationDialog、PlanPreview |
| 计划被阻断 | 计划包含 error 诊断或目标上下文不足 | InlineError、DisabledAction |
| Cleanup 确认 | 新计划包含旧 managed 目标 | ConfirmationDialog、CheckList |
| 应用中与结果 | 用户确认无阻断计划 | Progress、ResultSummary、InlineError |

## 交互行为

- **创建目标组合：** 用户选择配置组和一个或多个 Agent。Agent 项目目录与 Agent 组成项目级目标；自定义目录只使用 direct 语义。
- **阻止混合目标：** 用户同时选择标准 Agent 与自定义 direct 目录时，系统禁用保存并要求拆分目标组合。
- **漂移前置：** 标准 Agent 目标在漂移报告存在后开放“审查应用计划”；漂移检查期间禁用检查和应用动作。
- **审查策略：** 每个 skill 展示来源推荐、最终模式、策略来源和全部实际目标路径；未分类项保持阻断，不使用兼容分类兜底。
- **处理项目适用性：** 已绑定当前项目根的 Agent assessment 原样展示并随确认提交；缺失时用户可以返回补充分析，或显式 override 未决条件。
- **展示按需入口：** 计划包含用户级按需 skill 时，系统单独展示每个所选 Agent 的固定入口 skill 目录，并说明按需目标 skill 仍位于用户 catalog。
- **处理诊断：** warning 保留确认能力；error 禁用最终应用。没有已选 skill 时同样不能确认。
- **确认 cleanup：** 每个旧 managed 路径默认未选择。保存关系默认为开启；开启时全部候选必须选择，关闭时允许只执行用户明确选择的 cleanup。
- **执行计划：** 确认后系统基于当前来源与上下文重新计算计划。执行期间禁用关闭与重复提交。
- **完成刷新：** 成功后关闭确认框，展示写入目标数和实际清理数，并刷新漂移、目标历史和应用关系。
- **失败恢复：** 失败时保持确认框、计划和选择不变，用户可重试或取消后修正来源、Profile 或目标组合。
- **删除记录：** 删除目标组合或应用关系只移除 ArcForge 记录，不删除目标文件。

## 弹窗/对话框

| 名称 | 触发 | data-kit | 内容 |
|------|------|----------|------|
| Add or edit destination | 点击新增或编辑目标组合 | Sheet | 名称、配置组、Agent、Agent 项目目录、自定义 direct 目录和混用诊断 |
| Availability plan | 点击审查应用计划 | ConfirmationDialog | skill 模式、策略来源、目标目录、项目适用性证据、用户 override、入口 skill、诊断、cleanup 和关系保存 |
| Drift diff | 点击查看差异 | Sheet | 内容漂移、策略漂移、目标额外项和 cleanup 候选 |

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
|---------|---------|---------|
| 目标组合为空 | Sheet 字段提示 | 选择 Agent 或自定义 direct 目录 |
| 项目目录缺少 Agent | Sheet 字段提示 | 选择至少一个 Agent |
| 标准与 direct 目标混用 | Sheet 字段提示 | 拆分为两个目标组合 |
| 来源清单或目标上下文无效 | 计划诊断列表 | 返回来源、Profiles 或目标组合修正 |
| 项目 assessment 缺失或与目标根不匹配 | 计划诊断与来源条件 | 补充绑定当前目标根的 Agent assessment，或由用户显式 override 缺失判断 |
| Cleanup 未完整授权 | 确认框字段提示 | 选择全部候选或关闭关系保存 |
| 应用失败 | 保留计划并显示错误 | 重试或取消后修正输入 |
| 漂移检查失败 | 目标详情错误 | 保留旧结果并重新检查 |
| 来源项目缺失 | 关系详情错误 | 返回 Skills 修复来源关系 |
| 配置组缺失 | 关系详情错误 | 返回 Profiles 修复配置组 |

## 加载策略

| 场景 | 策略 |
|------|------|
| 漂移检查 | 保留旧结果，禁用重复检查和应用动作 |
| 计划生成 | 保留目标组合详情，显示正在生成计划 |
| 应用中 | 保留完整计划和选择，禁用关闭与重复提交 |
| 完成刷新 | 先展示结果摘要，再刷新漂移、目标历史和应用关系 |
| 差异加载 | 先展示文件和策略条目，再按需加载内容差异 |
