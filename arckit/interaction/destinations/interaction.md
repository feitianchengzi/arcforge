# Destinations - 交互规范

## 交互策略

### 核心任务

用户在 Destinations 页面管理配置组应用目标和已保存的应用关系，检查来源与目标之间的漂移，并在写入前复核每个 skill 的实际可用性模式、单一 catalog 身份、版本决策和目标位置。

### 主路径

页面展示目标组合、目标历史和应用关系。用户选择目标组合后先检查漂移；标准 Agent 目标进入 availability-aware 计划，系统解析用户级常驻、项目级常驻和用户级按需目标，再展示来源推荐、最终模式、策略来源、实际目录、项目适用性提示、按需入口和旧路径清理候选。用户级按需 skill 以规范化名称聚合为一个 catalog 候选：内容相同则合并来源声明，有有效版本差异则展示升级或阻止降级，同版本异内容或缺少可比较版本的异内容进入来源冲突。项目级常驻 skill 使用与本次项目根绑定的 Agent assessment；没有 assessment 时，用户只能在看过未决条件后作显式 override。用户解决 catalog 冲突并确认计划后，系统重新计算并执行计划，随后刷新漂移和应用关系。自定义目录保持 direct 应用路径。

### 决策点

- 用户选择标准 Agent 目标、Agent 项目目录或自定义 direct 目录。
- 标准 Agent 目标与自定义 direct 目录不能处于同一目标组合；用户分别保存两个组合。
- 用户在检查漂移后决定是否打开 availability-aware 应用计划。
- 有多个同名来源声明时，用户根据版本、内容摘要、来源标签和提交证据决定是否接受自动升级；系统不以 sourceKey 创建第二个逻辑候选。
- 自动版本比较不能唯一确定内容时，用户必须显式选择一个来源；未选择前，Agent、CLI 和 Desktop 都不得加载或写入该 skill。
- 低版本来源不能覆盖当前高版本；如用户确需切换，必须先作显式来源决策并重新生成计划，普通确认不能绕过降级阻止。
- 项目级常驻 skill 没有可复用 assessment 时，用户决定返回 Agent 补充分析，或显式覆盖未决判断；系统不把用户覆盖显示为 Agent 结论。
- 用户决定是否保存应用关系；保存关系时必须确认全部旧 managed 目标，不保存关系时只清理明确勾选的候选。
- 用户根据阻断诊断返回目标组合、Profiles 或来源清单修正输入。

### 信息揭示

目标组合详情先展示来源、配置组、解析后的目标和最近漂移结果。应用计划按 skill 展示来源推荐、最终模式、策略来源和实际目录；项目级常驻项同时展示来源维护的条件、取证提示、澄清问题和已有 assessment。用户级按需项展示规范化 skill 名称、当前与传入版本、决策结果、平铺 catalog 目录和合并后的来源声明，并另行展示固定入口 skill 的用户级 Agent 目录。冲突时才展开每个来源的版本、内容摘要、来源标签和可用提交证据；sourceKey 仅作为诊断用来源身份，不作为候选名称或目录。诊断、显式 override、来源选择、cleanup 候选和关系保存约束只在计划确认阶段揭示。

### 状态流

无目标组合时显示空状态。新增或编辑目标进入 Sheet。目标组合保存后进入漂移检查；availability-aware 目标只有获得漂移报告后才可审查应用计划。同名内容一致时直接形成一个 ready 候选并合并来源声明；高版本替换低版本时形成 upgrade；传入版本更低时保持现有候选并阻断 downgrade；无法安全比较时进入 conflict。冲突来源选择绑定当前计划快照，选择后必须重新生成计划；旧 sourceKey 分层目录只进入独立 cleanup 确认，未确认不得删除。缺少项目 assessment 时保持阻断，用户显式 override 后仅解除对应诊断；其它 error 仍阻断写入。执行期间禁用关闭和重复提交。成功后关闭计划、刷新漂移和关系；失败时保留计划、assessment、override、来源选择和其它选择以便重试或取消。

### 反馈与恢复

目标组合无 Agent、项目目录缺少 Agent、标准与 direct 目标混用时就地说明原因。计划 warning 保持可继续，error 阻断写入。版本升级明确标注旧版本到新版本；降级阻止说明保留的当前版本，冲突说明为何版本不足以判断“最新”，不猜测来源优先级。项目 assessment 缺失时展示来源条件和 override 的事实含义；选择 override 后隐藏已解除的缺失诊断，不改变其它诊断。保存关系但 cleanup 未全部选择时说明解除阻断的两种方式：选择全部候选，或关闭关系保存。写入失败保留计划、assessment、override、来源选择、cleanup 和关系保存选择。漂移检查失败保留上次成功结果和失败原因。

### 输入输出边界

输入包括目标组合名称、配置组、Agent 目标、Agent 项目目录、自定义 direct 目录、Agent assessment、用户显式 override、同名冲突来源选择、漂移检查、cleanup 选择、关系保存选择和最终确认。输出为只读可用性计划、每个逻辑 skill 的 catalog 状态与版本决策、项目适用性证据、漂移报告、实际写入结果、清理结果、目标历史和可选应用关系。Agent 与 CLI 的 catalog 列表只返回一个逻辑候选及其 ready/conflict 状态；冲突候选 fail closed，并给出返回 ArcForge 解决来源的治理提示。目标组合或关系记录删除不删除已安装文件。

## 页面状态

| 状态 | 触发条件 | data-kit 关键控件 |
|------|---------|-----------------|
| 目标组合与漂移 | 进入页面或选择目标组合 | DestinationList、DriftSummary |
| 添加或编辑目标 | 用户点击新增或编辑 | Sheet |
| 可用性计划与 Catalog 决策 | 标准 Agent 目标已有漂移报告，用户点击审查计划 | ConfirmationDialog、PlanPreview、VersionDecision |
| Catalog 冲突与降级阻断 | 同名来源无法安全合并，或传入版本低于当前版本 | ConflictList、SourceChoice、DisabledAction |
| 计划被阻断 | 计划包含其它 error 诊断或目标上下文不足 | InlineError、DisabledAction |
| Cleanup 确认 | 新计划包含旧 managed 目标或旧 sourceKey 分层 catalog 目录 | ConfirmationDialog、CheckList |
| 应用中与结果 | 用户确认无阻断计划 | Progress、ResultSummary、InlineError |

## 交互行为

- **创建目标组合：** 用户选择配置组和一个或多个 Agent。Agent 项目目录与 Agent 组成项目级目标；自定义目录只使用 direct 语义。
- **阻止混合目标：** 用户同时选择标准 Agent 与自定义 direct 目录时，系统禁用保存并要求拆分目标组合。
- **漂移前置：** 标准 Agent 目标在漂移报告存在后开放“审查应用计划”；漂移检查期间禁用检查和应用动作。
- **审查策略：** 每个 skill 展示来源推荐、最终模式、策略来源和全部实际目标路径；用户级按需项只显示一个规范化名称候选、版本决策、`~/.arcforge/catalog/<skill-name>` 路径和来源声明；未分类项保持阻断，不使用兼容分类兜底。
- **合并来源声明：** 同名同内容来源自动合并为一个 ready 候选；来源声明仍可检查，但 sourceKey 不出现在主名称或目录层级。
- **应用版本升级：** 仅在双方版本都是有效 SemVer 且传入版本更高时标记 upgrade，并清楚展示 `current → incoming`；同版本异内容不得自动覆盖。
- **阻止降级：** 传入有效版本低于当前版本时保留当前内容并禁用普通确认；提示用户选择来源并重新生成计划，而不是把低版本称为最新。
- **解决同名冲突：** 同版本异内容，或任一异内容来源缺少有效版本时，展开版本、摘要、来源标签和提交证据，要求用户单选来源；未选中时所有加载与写入动作保持禁用，选择后重新计划。
- **处理项目适用性：** 已绑定当前项目根的 Agent assessment 原样展示并随确认提交；缺失时用户可以返回补充分析，或显式 override 未决条件。
- **展示按需入口：** 计划包含用户级按需 skill 时，系统单独展示每个所选 Agent 的固定入口 skill 目录，并说明按需目标 skill 仍位于用户 catalog。
- **处理诊断：** warning 保留确认能力；error 禁用最终应用。没有已选 skill 时同样不能确认。
- **确认 cleanup：** 每个旧 managed 路径和旧 `catalog/<sourceKey>/<skill-name>` 目录默认未选择。旧目录清理与新平铺目录写入分开确认；保存关系默认为开启，开启时全部候选必须选择，关闭时允许只执行用户明确选择的 cleanup。
- **执行计划：** 确认后系统基于当前来源与上下文重新计算计划。执行期间禁用关闭与重复提交。
- **完成刷新：** 成功后关闭确认框，展示写入目标数和实际清理数，并刷新漂移、目标历史和应用关系。
- **失败恢复：** 失败时保持确认框、计划和选择不变，用户可重试或取消后修正来源、Profile 或目标组合。
- **删除记录：** 删除目标组合或应用关系只移除 ArcForge 记录，不删除目标文件。

## 弹窗/对话框

| 名称 | 触发 | data-kit | 内容 |
|------|------|----------|------|
| Add or edit destination | 点击新增或编辑目标组合 | Sheet | 名称、配置组、Agent、Agent 项目目录、自定义 direct 目录和混用诊断 |
| Availability plan | 点击审查应用计划 | ConfirmationDialog | skill 模式、策略来源、目标目录、项目适用性证据、用户 override、入口 skill、诊断、cleanup 和关系保存 |
| Drift diff | 点击查看差异 | Sheet | 内容漂移、策略漂移、目标额外项和 cleanup 候选 |

## 错误处理

| 错误类型 | 展示方式 | 恢复操作 |
|---------|---------|---------|
| 目标组合为空 | Sheet 字段提示 | 选择 Agent 或自定义 direct 目录 |
| 项目目录缺少 Agent | Sheet 字段提示 | 选择至少一个 Agent |
| 标准与 direct 目标混用 | Sheet 字段提示 | 拆分为两个目标组合 |
| 来源清单或目标上下文无效 | 计划诊断列表 | 返回来源、Profiles 或目标组合修正 |
| Catalog 降级尝试 | 当前与传入版本对比及阻断提示 | 保留当前版本；显式选择来源后重新生成计划 |
| Catalog 同版本异内容 | 来源冲突清单 | 检查摘要与来源证据，显式选择一个来源后重新生成计划 |
| Catalog 缺少有效版本且内容不同 | 来源冲突清单 | 补充有效 SemVer，或显式选择一个来源后重新生成计划 |
| 项目 assessment 缺失或与目标根不匹配 | 计划诊断与来源条件 | 补充绑定当前目标根的 Agent assessment，或由用户显式 override 缺失判断 |
| Cleanup 未完整授权 | 确认框字段提示 | 选择全部候选或关闭关系保存 |
| 应用失败 | 保留计划并显示错误 | 重试或取消后修正输入 |
| 漂移检查失败 | 目标详情错误 | 保留旧结果并重新检查 |
| 来源项目缺失 | 关系详情错误 | 返回 Skills 修复来源关系 |
| 配置组缺失 | 关系详情错误 | 返回 Profiles 修复配置组 |

## 加载策略

| 场景 | 策略 |
|------|------|
| 漂移检查 | 保留旧结果，禁用重复检查和应用动作 |
| 计划生成 | 保留目标组合详情，显示正在聚合同名来源并计算版本决策 |
| 应用中 | 保留完整计划和选择，禁用关闭与重复提交 |
| 完成刷新 | 先展示结果摘要，再刷新漂移、目标历史和应用关系 |
| 差异加载 | 先展示文件和策略条目，再按需加载内容差异 |
